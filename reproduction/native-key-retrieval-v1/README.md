# Exact native-key positional ablation

The same bounded pose retrieval now archives original post-RoPE keys instead of canonical keys moved to recent virtual times. All other bank, selection and attention-budget settings stay fixed. This was declared before generation in ../native-key-retrieval-plan.json. It is separate from the frozen virtual-key candidate used in memory validation.

On GC007 seed42 short turn-return, native-key retrieval recovers the starting landmark and the blinded reviewer prefers it to stock. On the delayed return it briefly reconstructs the original facade but overshoots and adds a hallucinated block; the reviewer says neither reaches the starting viewpoint, while noting better landmark memory than stock. These outcomes do not justify replacing the frozen virtual-position candidate, whose delayed return was stronger.

Native camera audits and exact raw-pixel prefixes pass in both pairs. Metadata records exact native key storage. Unit tests verify that archived native keys exactly equal the source native cache slices. Complete videos, contact sheets, manifests, metrics and blinded assessments are retained in each subdirectory. Stock videos and manifests are in ../context34-v1/ and ../delayed-return-v1/. No training or output editing occurs.
